## **Session 1: Introduction to Web Design**

### **1. How Browsers Render HTML + CSS**

When you open a website, the browser (like Google Chrome) does several things behind the scenes:

* **Step 1: Fetch files**
  It downloads HTML, CSS, and other assets (images, fonts, scripts).

* **Step 2: Parse HTML → DOM**
  HTML is converted into a **DOM (Document Object Model)** — a tree-like structure representing the page.

* **Step 3: Parse CSS → CSSOM**
  CSS is turned into a structure that defines styles for elements.

* **Step 4: Combine → Render Tree**
  DOM + CSSOM = Render Tree (what actually gets displayed).

* **Step 5: Layout & Paint**
  The browser calculates positions (layout) and draws pixels (paint) on screen.

👉 Key idea: Browsers don’t “read HTML like text”—they **build a structured visual model**.

---

### **2. Front-End vs Back-End Development**

| Aspect     | Front-End                      | Back-End                          |
| ---------- | ------------------------------ | --------------------------------- |
| What it is | What users see & interact with | Server-side logic & data handling |
| Languages  | HTML, CSS, JavaScript          | Python, Java, Node.js, PHP        |
| Runs on    | Browser                        | Server                            |
| Focus      | UI/UX, layout, responsiveness  | Databases, APIs, authentication   |

👉 Simple analogy:

* Front-end = **restaurant dining area (what you see)**
* Back-end = **kitchen (how things work behind the scenes)**

---

### **3. Developer Tools Overview (Chrome DevTools)**

**Chrome DevTools** is built into Chrome and is essential for debugging and learning.

**Key Panels:**

* **Elements** → Inspect and edit HTML/CSS
* **Styles** → Modify CSS live
* **Console** → Run JavaScript & see errors
* **Network** → View loading requests
* **Application** → Storage, cookies, etc.

👉 Shortcut:

* Right-click → **Inspect**
* Or press `Ctrl + Shift + I`

---

Use Instagram as a real-world example:

* Open Instagram in Chrome

  * Nested structure (divs inside divs)

### **5. Understanding the DOM (Core Concept)**

The **DOM** is a tree structure like this:

```
<html>
  <body>
    <h1>Hello</h1>
    <p>Welcome</p>
  </body>
</html>
```

Becomes:

```
HTML
 └── BODY
      ├── H1
      └── P
```

**Important concepts:**

* Parent / Child relationships
* Nesting
* Elements vs Nodes
* Classes & IDs

👉 Why it matters:

* JavaScript interacts with the DOM
* CSS targets DOM elements
* DevTools shows the DOM live

* How a browser turns code into visuals
* The role of front-end vs back-end
* How to inspect and experiment with real websites
* The DOM as the foundation of everything in web design

## **Session 2: HTML Page Structure**

### **1. HTML Boilerplate (Basic Structure)**

Every HTML page starts with a standard skeleton:

```html
<!DOCTYPE html>
<html>
<head>
    <title>My Page</title>
</head>
<body>
    <h1>Hello World</h1>
</body>
</html>
```

**Breakdown:**

* `<!DOCTYPE html>` → Tells the browser this is HTML5
* `<html>` → Root of the document
* `<head>` → Metadata (not visible on page)
* `<title>` → Tab title
* `<body>` → Visible content

👉 Key idea: The browser (like Google Chrome) reads this and builds the DOM you learned earlier.

---

### **2. Common HTML Tags**

#### **Headings & Paragraphs**

```html
<h1>Main Heading</h1>
<h2>Subheading</h2>
<p>This is a paragraph.</p>
```

* `<h1>` to `<h6>` → hierarchy of importance
* `<p>` → blocks of text

---

#### **Lists**

**Unordered List (bullets):**

```html
<ul>
  <li>Apple</li>
  <li>Banana</li>
</ul>
```

**Ordered List (numbers):**

```html
<ol>
  <li>Step 1</li>
  <li>Step 2</li>
</ol>
```

---

#### **Anchors (Links)**

```html
<a href="https://www.instagram.com">Visit Instagram</a>
```

* `href` → destination URL
* Opens web pages like Instagram

---

#### **Images**

```html
<img src="profile.jpg" alt="My Photo" width="200">
```

* `src` → image path
* `alt` → accessibility text

---

#### **Tables**

```html
<table border="1">
  <tr>
    <th>Name</th>
    <th>Age</th>
  </tr>
  <tr>
    <td>John</td>
    <td>20</td>
  </tr>
</table>
```

* `<table>` → container
* `<tr>` → row
* `<th>` → header cell
* `<td>` → data cell

---

Session 3: Forms & Inputs
1. What Are Forms?

Forms allow users to send data to a server—this is one of the first bridges between front-end and back-end.

👉 Examples:

Login pages
Sign-up forms
Search bars
2. Basic Form Structure
<form action="/submit" method="POST">
    <!-- form elements go here -->
</form>

Key attributes:

action → where the data is sent
method → how data is sent (GET or POST)

👉 Focus today: POST (used for sensitive or large data)

3. Common Form Elements
Input Fields
<input type="text" placeholder="Enter name">
<input type="email" placeholder="Enter email">
<input type="password" placeholder="Enter password">

Common types:

text, email, password, number, date
Labels (Important for UX & Accessibility)
<label for="name">Name:</label>
<input type="text" id="name">

👉 Clicking the label focuses the input—small detail, big usability win.

Dropdown (Select)
<select>
  <option>Student</option>
  <option>Developer</option>
</select>
Textarea
<textarea placeholder="Write your bio"></textarea>
Buttons
<button type="submit">Register</button>
4. Validation Attributes (Client-Side)

HTML gives built-in validation without JavaScript:

<input type="email" required>
<input type="password" minlength="6" required>

Useful attributes:

required → must be filled
minlength / maxlength
pattern → custom regex validation

👉 Key idea: Validation happens before sending data

5. Demo: Registration Form (Social Bio Link App)

Students build a simple sign-up form:

<!DOCTYPE html>
<html>
<head>
    <title>Register</title>
</head>
<body>

<h1>Create Your Profile</h1>

<form action="/register" method="POST">

    <label for="name">Name:</label><br>
    <input type="text" id="name" name="name" required><br><br>

    <label for="email">Email:</label><br>
    <input type="email" id="email" name="email" required><br><br>

    <label for="role">Role:</label><br>
    <select id="role" name="role">
        <option>Student</option>
        <option>Creator</option>
        <option>Developer</option>
    </select><br><br>

    <label for="bio">Bio:</label><br>
    <textarea id="bio" name="bio"></textarea><br><br>

    <label for="password">Password:</label><br>
    <input type="password" id="password" name="password" minlength="6" required><br><br>

    <button type="submit">Register</button>

</form>

</body>
</html>
6. Depth: Understanding POST in DevTools

Use Chrome DevTools to show what happens behind the scenes:

Steps:

Open DevTools (Ctrl + Shift + I)
Go to Network tab
Submit the form
Click the request (e.g., /register)

What students should observe:

Request Method: POST
Form Data: key-value pairs (name, email, etc.)
Headers: metadata about the request

👉 Important insight:

The browser sends data as a HTTP request
Back-end receives and processes it
7. Conceptual Depth (What’s Really Happening)
Form → converts inputs into key-value pairs
Browser → sends HTTP request
Server → processes and responds

👉 Example:

name=John&email=john@example.com
8. Suggested Hands-On Tasks
Add a phone number field
Add validation (required + minlength)
Add another dropdown option
Try submitting and inspect in DevTools

## **Session 4: Semantic HTML5**

### **1. What is Semantic HTML?**

Semantic HTML uses tags that **describe meaning**, not just layout.

👉 Instead of using generic `<div>` everywhere, we use meaningful elements like:

* `<header>`
* `<nav>`
* `<article>`
* `<footer>`

**Why it matters:**

* Better readability for developers
* Improved accessibility (screen readers)
* Helps search engines understand content

---

### **2. Key Semantic Tags**

#### **`<header>`**

Represents the top section of a page or section.

```html id="jpf1q5"
<header>
  <h1>My Website</h1>
</header>
```

---

#### **`<nav>`**

Used for navigation links.

```html id="qmyh6n"
<nav>
  <a href="#">Home</a>
  <a href="#">About</a>
</nav>
```

---

#### **`<article>`**

Independent, reusable content (like a post or video card).

```html id="pl7w8g"
<article>
  <h2>Blog Title</h2>
  <p>Content goes here...</p>
</article>
```

---

#### **`<footer>`**

Bottom section with additional info.

```html id="7g4uvg"
<footer>
  <p>© 2026 My Website</p>
</footer>
```

---

#### **Other Useful Tags (Mention Briefly)**

* `<section>` → groups related content
* `<aside>` → side content (ads, suggestions)
* `<main>` → main content area

---

### **3. Semantic vs Non-Semantic**

| Non-Semantic | Semantic Equivalent     |
| ------------ | ----------------------- |
| `<div>`      | `<header>`, `<section>` |
| `<div>`      | `<article>`             |
| `<div>`      | `<footer>`              |

👉 Key idea:
Semantic tags **tell a story about the page structure**, not just display it.

---

### **4. Demo: YouTube-Style Page Layout**

---

### **5. Teaching Focus (Depth)**

Emphasize:

* **Structure ≠ Style**
  Semantic HTML is about meaning, not appearance

* **Accessibility benefits**
  Screen readers rely on semantic tags

* **SEO basics**
  Search engines better understand structured content

* **Replace “div soup” mindset**
  Encourage intentional tag usage

---

## **Session 5: Introduction to CSS 3**

### **1. What is CSS?**

CSS (**Cascading Style Sheets**) controls the **appearance** of HTML.

👉 If HTML is the structure, CSS is the **design layer**:

* Colors
* Fonts
* Spacing
* Layout

---

### **2. Ways to Apply CSS**

#### **Inline CSS**

```html id="6g3e0z"
<p style="color: red;">Hello</p>
```

* Applied directly to an element
* ❌ Not recommended for large projects

---

#### **Internal CSS**

```html id="2d8zbn"
<head>
  <style>
    p {
      color: blue;
    }
  </style>
</head>
```

* Defined inside `<style>` tag
* Good for small pages

---

#### **External CSS (Best Practice)**

```html id="k4wz0y"
<head>
  <link rel="stylesheet" href="styles.css">
</head>
```

```css id="t3j2yo"
p {
  color: green;
}
```

👉 Keeps HTML clean and reusable

---

### **3. CSS Selectors**

Selectors target HTML elements.

```css id="3htzvd"
/* Element selector */
p {
  color: blue;
}

/* Class selector */
.card {
  background-color: lightgray;
}

/* ID selector */
#title {
  font-size: 24px;
}
```

👉 Key idea:

* `.` → class
* `#` → id

---

### **4. Colors in CSS**

```css id="3fj0r2"
h1 {
  color: red;
}

p {
  color: #333333;
}

body {
  background-color: rgb(240, 240, 240);
}
```

**Types:**

* Named colors (`red`)
* HEX (`#000000`)
* RGB (`rgb(255,0,0)`)

---

### **5. Fonts**

```css id="zv94xv"
body {
  font-family: Arial, sans-serif;
}

h1 {
  font-size: 32px;
  font-weight: bold;
}
```

👉 Always include a fallback font (`sans-serif`, `serif`)

## **Session 6: Box Model & Positioning**

### **1. The CSS Box Model**

Every HTML element is a rectangular box made of:

```text
[ Margin ]
  [ Border ]
    [ Padding ]
      [ Content ]
```

#### **Breakdown**

* **Content** → text/image inside
* **Padding** → space inside the box
* **Border** → edge around the box
* **Margin** → space outside the box

---

#### **Example**

```css id="l4k9z2"
.card {
  width: 300px;
  padding: 20px;
  border: 2px solid black;
  margin: 10px;
}
```

👉 Key idea:
Spacing problems in UI usually come down to **margin vs padding confusion**.

---

### **2. Display Properties**

Controls how elements behave in layout:

```css id="7g5xk1"
div {
  display: block;
}

span {
  display: inline;
}

.card {
  display: inline-block;
}
```

#### **Types**

* **block** → full width (e.g., `<div>`)
* **inline** → only content width (e.g., `<span>`)
* **inline-block** → mix of both

👉 Important:
You can change how elements behave regardless of their default type.

---

### **3. Positioning in CSS**

Position determines where elements appear.

#### **Static (default)**

```css id="f0b5xq"
div {
  position: static;
}
```

---

#### **Relative**

```css id="5x1k4d"
.box {
  position: relative;
  top: 10px;
  left: 20px;
}
```

* Moves relative to its **original position**

---

#### **Absolute**

```css id="a0p3qw"
.child {
  position: absolute;
  top: 0;
  right: 0;
}
```

* Positioned relative to **nearest positioned parent**

---

#### **Fixed**

```css id="t1o7y8"
.navbar {
  position: fixed;
  top: 0;
  width: 100%;
}
```

* Stays fixed on screen (even when scrolling)

---
